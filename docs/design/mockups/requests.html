mockup This control is not part of the product. It switches the screen between the states this design has to cover, all of them over invented data.
No indexer service configured

This screen searches your indexers through Prowlarr and sends the grab to the download client Prowlarr already has. Without a Prowlarr there is nothing to query, and UsArr does not talk to indexers directly.

Add Prowlarr
Every search is free text matched against the release name — the type and the categories narrow what is searched, they do not give you an author, artist, album or title field. Book and Music look like structured modes and are not: Prowlarr can send a query string and nothing else, so Book cannot search by author and Music cannot search by artist. 9 of the 14 indexers here are invite-only, which is what coverage for music and books actually depends on.

mockup The numbers are the Newznab categories Prowlarr actually uses, and two of them are the ones people get wrong: 3030 Audio/Audiobook sits under 3000 Audio, not under 7000 Books, so an audiobook rule that sends 7020 finds nothing; and there is no manga category anywhere in the standard tree, so a comics search filtered on 7030 returns zero manga because Nyaa maps its literature categories to 7000 Books. Coverage also is not the same for every type: 403 of Prowlarr's 543 indexer definitions are type: private, and the trackers where music and books actually live — MyAnonaMouse, Bibliotik, Redacted, Orpheus — are invite-only, so Search-and-Grab for those two is materially thinner on public indexers than it is for film.

mockup A grab is acknowledged, not applied optimistically. The button writes a queued command and the row shows pending until Prowlarr answers. A failure changes that chip on the same visible row and raises a message carrying the upstream text verbatim, with Retry and Dismiss. The row never silently reverts. Grabbing the 26-day-old HDBits release above is wired to fail, so that path is reachable from this page.

mockup The external-link icon on each row opens the indexer's own page for that release. It is never a download link. Prowlarr's downloadUrl and magnetUrl carry its API key in the query string, and that key is full-admin, so neither field is sent to the browser at all: Grab posts an opaque release id to UsArr, and UsArr talks to Prowlarr.

mockup Grabs are recorded in provenance, so if a Sonarr or Radarr is added later and imports the file, the download id joins back to the release these indexers returned. UsArr does not track what happens to the download, and does not talk to a download client itself.

Nothing on this install imports a book, so a grab ends in your download client
Neither Audiobooks nor Ebooks has a request destination, and neither does Music or Comics: v0.1 connects no command sink, and Readarr — the *Arr that used to own books — was archived on 27 June 2025. Grabbing works and the file will download; after that no service renames it, moves it into a library, or tells UsArr what became of it. Audiobookshelf will show the book once the file is in /media/books, which is the folder it reports as watched for this library.
