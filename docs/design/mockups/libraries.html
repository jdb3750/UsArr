mockup This control is not part of the product. It switches the screen between the states this design has to cover, all of them over invented data.

A library is a name you own over containers your services already computed — a whole instance, a root folder, an upstream library id, or an *Arr tag. UsArr never reads a filesystem and never types a path: every container below was offered by the service that owns it. Services is the other half of this pair, and it is where credentials and health live.

mockup Ebooks is one library over one Kavita here and one library over two instances on the full stack, which is the same mechanism from the other side: a library is a name you own over containers, and the number of containers behind it is not the user's problem until one of them is. Three of these four libraries are bound to the same Kavita and the fourth is bound to nothing, which is what one catalogue source looks like.

mockup Audiobooks and Ebooks divide one Audiobookshelf library between them, split by edition format. Audiobookshelf's own model has one axis — mediaType is book or podcast — and the ebook/audiobook difference is a field on each item, so it cannot present the split itself. UsArr can, because it binds to the container and filters on format, and that is the clearest case of the organisation being better than the service's own. Ebooks then takes a second container from a second service, which is the other half of the same idea: a library is a name over containers, and neither the number of them nor which service owns them is fixed by the name.

Why each of those six reads the way it does: Audiobookshelf distinguishes an ebook from an audiobook per item, not per library, so it cannot offer the Audiobooks/Ebooks split itself — UsArr can, because it binds to the container and filters on format. Kavita declares its library type — Manga, Comic or Book — but which UsArr kind that maps to is still a judgement, so the select is not read-only. The Manga container answers and reports zero series, which is a different fact from a library that failed to sync, so it is proposed rather than dropped — and renaming it to Comics makes it join that library as a second source instead of becoming a parallel one. Podcasts is declined because there is no podcast media type to map it to; its 61 items are not imported and not hidden, they stay in Audiobookshelf where they already work.

mockup The correction tables ship in migration 0001; this surface is v0.3, and 16.0 caps it there. It is drawn in full here so the bound can be reviewed before the schema is written, not because it ships with the four screens above.

Four verbs and five fields, and that bound is the design. A correction lives in UsArr, is keyed to UsArr's own identity, is never written back to the service, and is never cleared by a sync, a reconciliation sweep or a tombstone expiry. LazyLibrarian's re-adding of books you marked ignored, because a rescan returned them with one piece of metadata different, is exactly what happens when corrections are keyed to the upstream's id instead. (LazyLibrarian is a v0.3 item here and is named as the failure it demonstrates, not as a service this install has.)
