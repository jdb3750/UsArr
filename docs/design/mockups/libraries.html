A library is a name you own over containers your services already computed — a whole instance, a root folder, an upstream library id, or an *Arr tag. UsArr never reads a filesystem and never types a path: every container below was offered by the service that owns it. Services is the other half of this pair, and it is where credentials and health live.

mockup Audiobooks and Ebooks are two libraries over one Audiobookshelf library, split by edition format. Audiobookshelf's own model has one axis — mediaType is book or podcast — and the ebook/audiobook difference is a field on each item, so it cannot present the split itself. UsArr can, because it binds to the container and filters on format, and that is the clearest case of the organisation being better than the service's own.

Renaming a proposal to match another makes it join that library as a second source rather than create a parallel one; the match ignores case and surrounding spaces, and the row says so the moment it happens. Editing any proposal also marks that library user-managed, after which a later connect can only offer to add sources — never reshape it.

Why each of those five reads the way it does: Audiobookshelf distinguishes an ebook from an audiobook per item, not per library, so it cannot offer the Audiobooks/Ebooks split itself — UsArr can, because it binds to the container and filters on format. Komga publishes no library type and does scan EPUB, so its kind is a guess and the select is not read-only. The Manga container answers and reports zero series, which is a different fact from a library that failed to sync, so it is proposed rather than dropped — and renaming it to Comics makes it join that library as a second source instead of becoming a parallel one. Podcasts is declined because there is no podcast media type to map it to; its 61 items are not imported and not hidden, they stay in Audiobookshelf where they already work.

mockup Nothing on this screen asks for a path. Every container above was named by the service that owns it: an Audiobookshelf library id and a Komga library id. That is the whole difference between binding to a service and scanning a disk, and it is why the kind is editable here — nothing was inferred from a folder name, so nothing breaks when you change it.

mockup The correction tables ship in migration 0001; this surface is v0.3, and 16.0 caps it there. It is drawn in full here so the bound can be reviewed before the schema is written, not because it ships with the four screens above.

Four verbs and five fields, and that bound is the design. A correction lives in UsArr, is keyed to UsArr's own identity, is never written back to the service, and is never cleared by a sync, a reconciliation sweep or a tombstone expiry. LazyLibrarian's re-adding of books you marked ignored, because a rescan returned them with one piece of metadata different, is exactly what happens when corrections are keyed to the upstream's id instead. (LazyLibrarian is a v0.3 item here and is named as the failure it demonstrates, not as a service this install has.)
