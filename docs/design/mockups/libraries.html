mockup A library is a name you own over containers your services already computed — a whole instance, a root folder, an upstream library id, or an *Arr tag. UsArr never reads a filesystem and never types a path: every container below was offered by the service that owns it. Services is the other half of this pair, and it is where credentials and health live.

No libraries, because no services

A library is a binding to something a service already has, so there is nothing to define until a service exists. Connect one and UsArr proposes the libraries it can see, each of which you can rename, retype or refuse before anything is saved.

mockup Audiobooks and Ebooks are two libraries over one Audiobookshelf library, split by edition format. Audiobookshelf's own model has one axis — mediaType is book or podcast — and the ebook/audiobook difference is a field on each item, so it cannot present the split itself. UsArr can, because it binds to the container and filters on format, and that is the clearest case of the organisation being better than the service's own.

Exactly one, required, and editable. Changing it re-derives membership from what the services report and changes nothing upstream. It is editable because UsArr has no scanner: nothing here was inferred from a path or a filename, which is the failure class every scanning tool's mixed-library mode falls into.
Empty means every format. This is the field that lets Audiobooks and Ebooks be two libraries over one Audiobookshelf library: an audiobook and an ebook are two editions of the same book, and only the format tells them apart.

mockup The correction tables ship in migration 0001; this surface is v0.3, and 16.0 caps it there. It is drawn in full here so the bound can be reviewed before the schema is written, not because it ships with the four screens above.

Four verbs and five fields, and that bound is the design. A correction lives in UsArr, is keyed to UsArr's own identity, is never written back to the service, and is never cleared by a sync, a reconciliation sweep or a tombstone expiry. LazyLibrarian's re-adding of books you marked ignored, because a rescan returned them with one piece of metadata different, is exactly what happens when corrections are keyed to the upstream's id instead. (LazyLibrarian is a v1.0 item here and is named as the failure it demonstrates, not as a service this install has.)
