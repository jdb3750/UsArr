General settings are not drawn in this mockup. The five v0.1 screens are the scope.

Only the system tag namespaces ship in v0.1: type:, format:, source:, quality:, indexer:. They render as chips you can filter by but not delete. A tag is not a library: a library is a single-kind container with sources and a destination, a tag is a cross-kind label, and a saved filter is a query. Aliases, virtual parents, the rule engine and saved filters are v1.0.

Theme and density live in the top bar of every screen, and both persist. There is no colour-impaired mode setting, because every status here is an icon and a word as well as a colour.

WCAG 2.2 SC 2.1.4 is a Level A criterion and it is satisfied by exactly one of three things: the shortcut can be turned off, it can be remapped, or it is active only on focus. "It also has a visible mouse equivalent" is not one of them — the criterion exists for speech-input users, whose dictation is typed into the page, and for anyone with a tremor. This switch is the "turn off", it covers /, l, j, k and ?, and it persists. Shortcuts that need a modifier are unaffected.

Lidarr lidarr
 v1.0 A request destination for Music. Never a catalogue source: Navidrome holds the music. Lidarr writes status: deleted into its own database when its metadata server returns 404 for an MBID — which is also what an MBID merge produces. Rendering that as a tombstone would hide an artist whose files are still on disk, so UsArr would show it as a claim about metadata, exclude it from the reconciliation sweep, and touch nothing.
artist 412 Supersilent: status deleted, last seen 12:41 14 albums and 1,208 tracks untouched; no tombstone written
LazyLibrarian lazylibrarian
 v1.0 A request destination for Ebooks, and deliberately not a source: its matching is a fuzzy ratio its own documentation recommends setting to 80–90%, which is not an identifier join. Capabilities are probed, not assumed: Add for (book, epub) and (book, mobi), and no Add for an audiobook at all. It reports its version as master and ships no tagged releases, so UsArr would pin the API shape it probed rather than a version number.
Kavita kavita
 v0.2 A second catalogue source for Ebooks and Comics. Komga already covers comics in v0.1, so no media type is lost by deferring it. Identifier matching is a paid subscription feature, so on an unsubscribed install every identifier field is null and the honest count has to say which side of the line each series sits on: 108 of 389 series resolved to a work identity, all 108 from an identifier embedded in the file itself; the remaining 281 are matched by title only, which is below the cross-media merge threshold. Its LibraryType 3 (Image) libraries would be declined outright — UsArr is not a photo manager and will not pretend a folder of images is a comic.
