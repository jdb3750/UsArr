mockup A library is a name you own over containers your services already computed — a whole instance, a root folder, an upstream library id, or an *Arr tag. UsArr never reads a filesystem and never types a path: every container below was offered by the service that owns it. Services is the other half of this pair, and it is where credentials and health live.

No libraries, because no services

A library is a binding to something a service already has, so there is nothing to define until a service exists. Connect one and UsArr proposes the libraries it can see, each of which you can rename, retype or refuse before anything is saved.

mockup A grab is acknowledged, not applied optimistically. The button writes a queued command and the row shows pending until Prowlarr answers. A failure changes that chip on the same visible row and raises a message carrying the upstream text verbatim, with Retry and Dismiss. The row never silently reverts. Grabbing the 26-day-old HDBits release above is wired to fail, so that path is reachable from this page.

mockup The external-link icon on each row opens the indexer's own page for that release. It is never a download link. Prowlarr's downloadUrl and magnetUrl carry its API key in the query string, and that key is full-admin, so neither field is sent to the browser at all: Grab posts an opaque release id to UsArr, and UsArr talks to Prowlarr.

mockup Grabs are recorded in provenance, so if a Sonarr or Radarr is added later and imports the file, the download id joins back to the release these indexers returned. UsArr does not track what happens to the download, and does not talk to a download client itself.
